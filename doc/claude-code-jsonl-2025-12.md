# Claude Code Session Log Structure Analysis (2025-12)

This document provides a comprehensive schema analysis of the JSONL log files generated by Claude Code in `~/.claude`.

## 1. Directory & File Organization

- **Global History**: `~/.claude/history.jsonl` (Cross-project command history).
- **Project Data**: `~/.claude/projects/{sanitized-path}/`.
    - **Session Logs**: `{UUID}.jsonl` (Main user-visible conversation).
    - **Agent Sidechains**: `agent-{ID}.jsonl` (Detailed execution traces for autonomous agents).

## 2. Common Log Fields

All log entries (regardless of `type`) generally share these metadata fields:

| Field        | Type             | Description                               |
| :----------- | :--------------- | :---------------------------------------- |
| `uuid`       | string (UUID)    | Unique ID for this log entry.             |
| `sessionId`  | string (UUID)    | The session ID this entry belongs to.     |
| `timestamp`  | string (ISO8601) | Time of occurrence.                       |
| `cwd`        | string           | Current working directory/project root.   |
| `gitBranch`  | string           | Active git branch at the time of logging. |
| `version`    | string           | Claude Code CLI version (e.g., `2.0.75`). |
| `userType`   | string           | User type (e.g., `"external"`). Present in ALL entries. |
| `isSidechain`| boolean          | Whether this entry is part of a sidechain. |
| `parentUuid` | string \| null   | Parent entry UUID for threading.          |

## 3. Log Entry Types

The `type` field discriminates the schema. Identified types are:

### 3.1 `type: "user"`
Represents input from the user or tool results.

```json
{
  "type": "user",
  "userType": "external", // e.g., "external"
  "message": {
    "role": "user",
    "content": "string or array of content blocks (including tool_result)"
  },
  "todos": [], // Array of associated todo items (optional)
  "thinkingMetadata": { ... }, // Configuration for model thinking (optional)
  "isMeta": boolean, // True for meta messages (e.g., system reminders)
  "slug": "string", // Human-readable name (present in tool_result entries)
  "toolUseResult": { // Present when content contains tool_result
    "type": "text",
    "file": {
      "filePath": "/abs/path",
      "content": "...",
      "numLines": number,
      "startLine": number,
      "totalLines": number
    }
  },
  "isSidechain": boolean,
  "parentUuid": string | null
}
```

### 3.2 `type: "assistant"`
Represents responses from the AI model (text, thinking, tool usage).

```json
{
  "type": "assistant",
  "requestId": "req_...", // API Request ID
  "agentId": "string", // ID of the agent instance (if sidechain)
  "slug": "string", // Human-readable agent name (e.g., "dapper-orbiting-patterson")
  "message": {
    "id": "msg_...", // Message ID from API
    "type": "message", // Always "message"
    "role": "assistant",
    "model": "claude-...", // Model identifier (e.g., "claude-opus-4-5-20251101")
    "content": [
      // Can be Text Block or Tool Use Block
      {
        "type": "text",
        "text": "..."
      },
      {
        "type": "tool_use",
        "id": "toolu_...",
        "name": "Read | Glob | Grep | ...",
        "input": { ... } // Arguments for the tool
      }
    ],
    "stop_reason": null | "end_turn" | "tool_use",
    "stop_sequence": null | string,
    "usage": {
      "input_tokens": number,
      "output_tokens": number,
      "cache_creation_input_tokens": number,
      "cache_read_input_tokens": number,
      "cache_creation": {
        "ephemeral_5m_input_tokens": number,
        "ephemeral_1h_input_tokens": number
      },
      "service_tier": "standard" // Service tier
    }
  },
  "isSidechain": boolean,
  "parentUuid": string | null // Links to the triggering user message or parent event
}
```

### 3.3 `type: "file-history-snapshot"`
Tracks file content changes for revert/diff capabilities.

```json
{
  "type": "file-history-snapshot",
  "messageId": "UUID", // Links to the user message that triggered this snapshot
  "snapshot": {
    "messageId": "UUID",
    "trackedFileBackups": {
      "/abs/path/to/file": "file content..." // Or a reference to content
    },
    "timestamp": "ISO8601"
  },
  "isSnapshotUpdate": boolean
}
```

### 3.4 `type: "system"`
Represents system-level events or local slash commands (e.g., `/usage`, `/help`).

```json
{
  "type": "system",
  "subtype": "local_command", // e.g., "local_command"
  "level": "info", // Log level
  "content": "<command-name>...</command-name>", // XML-like structured content
  "isMeta": boolean
}
```

### 3.5 `type: "queue-operation"`
Tracks asynchronous background operations or agent notifications.

```json
{
  "type": "queue-operation",
  "operation": "enqueue", // e.g., "enqueue"
  "content": "<agent-notification>...</agent-notification>" // XML-structured notification
}
```

### 3.6 `type: "summary"`
Updates session metadata, such as the conversation title.

```json
{
  "type": "summary",
  "summary": "Generated Conversation Title",
  "leafUuid": "UUID" // The last message ID covered by this summary
}
```

## 4. Relationship Graph

- **Sequencing**: Entries are ordered by `timestamp`.
- **Threading**:
    - `user` messages start a thread (or continue one).
    - `assistant` messages usually follow `user` messages or `tool_result` (which are inside `user` blocks in some schemas, or implicit).
    - **Sidechains**:
        - A `user` message with `isSidechain: true` (or an `assistant` spawning one) creates a branch.
        - Events in `agent-{ID}.jsonl` link back to the main session via `parentUuid`.
        - `parentUuid` points to the *Message ID* in the main session that spawned the agent.
